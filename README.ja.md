# Virtuoso Standard-Cell Layout

[English](README.md) | [日本語](README.ja.md) | [繁體中文](README.zh-TW.md)

Cadence Virtuoso 上で、スタンダードセルまたはカスタムデジタルのブロックを、
空のアーティファクト集合から、根拠の揃った配線完了状態まで持っていくための
エージェント skill です。

スタンダードセルの自動化は、たいてい同じ場所で壊れます。`physConfig` が機能
しないままレイアウトだけが作られる。セルが誤った境界図形を基準に置かれる。
電源レールが繋がっていると決めつけられる。完了率が 100% と表示されただけで
配線成功と見なされる。ダブルカット要求がそのまま保証として扱われる。この
skill は、その失敗点を中心に組み立てています。

```text
Stage order      artifact set -> placement -> M1 supply tracks -> route
                 feedback -> signal routing -> tap/DRC -> LVS interpretation

Evidence layers  command-completed -> connectivity-closed
                 -> detailed-geometry-closed -> via-contract-closed
                 -> saved-readback-closed
```

各矢印は形式的な手順ではなくゲートです。後段が前段の抜けを埋めることはなく、
ある層で通った結果が別の層の代わりになることもありません。

## 対象範囲

- **アーティファクトの確立。** レイアウト作成、`physConfig` 作成、ソース生成、
  config と connectivity 参照の割り当て、アクティブ Binder の更新、クロス
  プローブ検証を、それぞれ別の状態遷移として扱います。Layout XL の起動に
  成功したことは、その後の状態が存在する証明にはなりません。
- **実境界からの配置。** インスタンスや master のバウンディングボックスでは
  なく PR 境界図形を使います。許される変換の集合は推測せずライブラリから
  読み戻します。保護されたグループは剛体として平行移動します。
- **配置と等価ピンの同時探索。** 合法な左右反転、3 端子の共有ツリー形状、
  直列チェーンのクラスタリング、明示的な固定端点を、ペアごとの距離ではなく
  ネット全体のコストとして評価します。
- **占有ポリシー。** 単一高さを既定とし、デカップリング容量優先で整数サイト
  の厳密被覆を求め、狭い残余ギャップだけを合法なフィラーで閉じます。多高さ
  セルはトランザクションごとに明示的に有効化する必要があります。
- **電源トラック。** 配線フットプリントから寸法を決める均一長の M1 電源・
  グラウンドトラック。外側上下の 2 本のレールはグラウンドであることと、
  セルレールに物理的に接触していることを要求します。
- **配線の受け入れ。** 上記の順序立った証拠ベクタと、ルータ自身の要約では
  なくデータベースから読み戻す厳密な実効 via 配列ゲート。
- **タップ挿入。** ラッチアップ間隔をプロセスごとに確認し、行ごとの有限個数
  と端部区間に変換し、その実行が許可されている場合にターゲット自身の DRC で
  検証します。
- **書き込みの安全性。** 単一ライターのリース、有限のリクエスト予算、バッチ
  化、そして曖昧な戻り値の後に盲目的な再試行をしない 1 回だけの照合。

## Skill としての導入

ディレクトリごとエージェントの skill フォルダへコピーします。

```bash
cp -R virtuoso-standard-cell-layout ~/.codex/skills/virtuoso-standard-cell-layout
```

中身は素の Markdown と、標準ライブラリだけで動く Python 2 ファイルです。
ビルドも依存関係の導入も不要です。同梱のテストは次のように実行します。

```bash
python3 scripts/test_layout_plan.py
```

## 正直な限界

- この skill は DRC、LVS、抽出、サインオフを**実行しません**し、ルールデッキ
  も同梱していません。候補を準備し、別途バインドされた検証フローが現在の
  プロセスルールで出した結果を解釈する立場です。
- ライブのレイアウトアダプタも**同梱していません**。同梱の Python は純粋な
  計算だけで、データベース、ファイルシステム、ネットワークに触れません。
  実セッションに届くコールバックは、あなたのプロジェクトが用意します。
- ここに記録した Route API の名前と意味論は、特定のインストール世代を読んで
  得たものです。ベンダー資料もインストール済みシンボルもリリースによって
  異なります。使う前に、あなたのバージョンで正確なシグネチャを確認して
  ください。
- ハーフペリメータ長や最小全域木長といった幾何コストは**配置の代理指標**です。
  配線長が短くなった証拠にはならず、それだけを根拠に配線長改善を主張しては
  いけません。
- 作例に出てくる数値は確認手順の例であり、移植可能な既定値ではありません。
  プロセスルール、レイヤ名、合法な master、合法な向きは、すべて目の前の
  設計から取ります。

## 譲れない規則

1. **ライターは 1 つ。** ライブセッションのジオメトリライターは常に 1 つ
   だけです。読み手は変更が静止するまで待ち、制御をユーザーに返す前に
   リースを解放します。
2. **不合格の候補を保存しない。** 接続性、詳細ジオメトリ、または厳密な via
   契約に失敗した候補は、明示的にライブかつ未保存のままにし、最後に受け入れ
   たディスク状態を保ちます。
3. **曖昧な変更を再試行しない。** タイムアウトや曖昧な戻り値は結果不明です。
   有界の照合を 1 回だけ行い、盲目的な再試行、保存、後始末を先にしません。
4. **保護対象を保つ。** テキスト、ラベル、ピン図形、既存の配線、電源
   ジオメトリ、端子とネットの対応は、その正確なオブジェクトが許可された
   書き込み集合に入っていない限り保護されます。
5. **要求は保証ではない。** ルータにダブルカット via、最大ルール、push を
   要求したことは、それらが実行された証明になりません。データベースを
   読み戻し、正確な契約を要求してください。

## 適用範囲についての注記

これは実務用のエンジニアリング skill であり、仕様書ではありません。特定の
ツール世代で確認した運用を書いた規則もあれば、実際の失敗から得た教訓を
記録した箇所もあります。プロセス、ライブラリ、サイトの慣習に依存する規則は
その旨を書いてあります。ローカルの慣習を移植可能な規則へ一般化しないで
ください。
